    Grounded retrieval

    Every sentence traces back to a paragraph you can read.

    Nyaya searches a corpus of Indian statutes and judgments, then answers only from what it found. Each claim carries a source tag, and each tag is checked against the passage it points at before you ever see it. When the corpus does not hold the answer, it says so instead of inventing one.

    Comparable matters

    How courts have decided matters like this one.

    Describe the facts and the charges. Nyaya finds the closest matters in a labelled corpus of Indian decisions, shows how each one actually ended, and explains what separates the two groups. It reports a pattern in past cases. It does not predict your result.

    Retrieval inspector

    See exactly what the index returns.

    This runs the hybrid search on its own, with no language model in the loop. It is the fastest way to check what the corpus actually holds on a topic, and it costs nothing and needs no API key. Each result shows its dense and keyword ranks so you can see which half of the retriever found it.

    Retrieval always runs locally, so search and sources work with no key at all. A key is only needed for written answers.

      Use your own key

      Paste a Groq, Gemini, Cloudflare, OpenAI or Hugging Face key. It is held in this browser only, sent with your requests, and never stored on the server.

      Cloudflare puts the account in the request URL, so a token on its own cannot address anything. Copy the Account ID from your Cloudflare dashboard overview.

      Retrieval

      How it works

      1. Route. The question is classified and rewritten into a retrieval query.
      2. Retrieve. Dense vectors and BM25 run in parallel and are fused by reciprocal rank.
      3. Answer. The model writes only from the retrieved passages.
      4. Verify. Each citation is matched against the passage it names. Anything that does not match is flagged in the answer.
